# 06. 작성 작업 종료와 콘솔 결과

사용자는 원고와 검토 결과를 볼 수 있어야 하며, 관리자가 판단할 내용이 남아 있어도 자동 작성 작업 자체는 종료할 수 있다. 이를 발행 승인과 구분한다.

## 실행 결과와 콘텐츠 상태

`run_result.outcome`은 실행 결과 객체의 값이다. 기존 Registry status 열에 새로운 문자열을 직접 넣지 않는다.

| run outcome | 의미 | 기존 콘텐츠 상태로 반영할 후보 |
|---|---|---|
| COMPLETED_READY | 모든 필수 검토 및 해당 revision의 사람 컨펌 완료 | READY_TO_PUBLISH |
| COMPLETED_REVIEW_PENDING | 원고/자동검토 작업 종료, 관리자 판단 남음 | READY_FOR_QA 유지 |
| REVISION_REQUIRED | 원고 오류 또는 편집 수정 남음 | REVISION_REQUIRED |
| NEEDS_EVIDENCE | 필요한 기술 근거/필수 자산 부족 | NEEDS_EVIDENCE |
| FAILED | 호출/로딩/파싱/저장 오류로 완료 불가 | 기존 상태 유지 + 실행 실패 기록 |

위 표는 의미 대응이며 전이 매트릭스를 우회하는 명령이 아니다. 현재 상태에서 허용되지 않는 전이는 승인된 상태 계약을 정비한 뒤 적용한다. 자동 검토 결과만으로 사람 컨펌을 대신하지 않는다.

## 콘솔 필수 출력

1. content_id, run_id, 작성 모델/버전, 시작·종료 시각, 원고 revision.
2. 선택한 부족 키워드, 주제/검색 의도, 주요 장비·기능 및 선택 이유.
3. 사용한 Fact/근거 수, 미검증 항목, 적용 규칙 ID/version, 컨텍스트 hash.
4. 초안과 재작성 비교, 각 피드백의 해결/미해결 상태.
5. 사용 이미지와 위치, 공식/자체/생성 구분, 승인 상태, URL 검사 결과.
6. 로지텍 AI 검토 결과: 확인/불일치/근거 부족/범위 외/오류를 분리한 목록.
7. 지식 업데이트 후보와 원고 오류 목록, 각 담당자·처리 상태.
8. 관리자 체크사항: 원고/이미지 위치, 판단할 질문, 필요한 자료, 발행 차단 여부, 처리 버튼.
9. 작성 작업 결과와 발행 가능 여부, 원고/미리보기/검토 보고서 경로.

`publish_ready`는 모든 필수 검토가 같은 revision/hash에 묶여 있고, blocking 항목이 해결되고, 원고·이미지 컨펌과 공개 URL 확인이 끝난 경우에만 true다. 오류/미검토는 별도 상태로 표시하고 0건 성공으로 처리하지 않는다.

## 결과 예시 — 형식 예시이며 실제 실행 결과 아님

```text
작성 작업: 종료 / 관리자 검토 대기
원고: r3 / 피드백 2건 해결
공식 검토: 확인 4, 불일치 0, 근거 부족 0, 범위 외 1
지식 대기열: 0건
관리자 체크: ADM-... ‘이 쇼룸 테스트를 실제로 수행했는가?’
필요 자료: 테스트 일자·장비 구성·관찰 기록
이미지: 공식 1, 생성 개념도 1 / 검토 완료
발행 가능: 아니오 — 실증 주장 확인 및 최종 원고 컨펌 필요
```

콘솔에서 관리자는 현재 revision을 보고 판단해야 한다. 원고가 바뀌면 기존 컨펌은 새 원고의 승인이 아니다. final.md와 발행 HTML은 승인된 스냅샷에서만 만들고, 미승인 draft preview는 따로 표시한다.

게시 후 실제 URL/post ID·게시일·게시된 revision을 등록한다. 추적은 해당 글을 대상으로 하며 블로그의 다른 글 노출을 이 원고 성과로 기록하지 않는다. 성과 리뷰는 다음 부족 키워드 진단과 기존 글 개선 제안으로 연결한다.
