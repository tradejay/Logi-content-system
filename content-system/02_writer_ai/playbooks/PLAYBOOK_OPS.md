# Playbook 경량 운영 및 진화 가이드 (PLAYBOOK_OPS.md)

- **핵심 철학**: "처음부터 완벽하게 설계하지 않는다. **쓰면서 발견 ➔ 바로 수정 ➔ 반복되면 분리/추가**한다."
- **목적**: 거창한 아키텍처 변경 없이 현장 글쓰기 경험을 Playbook의 자연스러운 진화로 흡수

---

## 1. 5단계 경량 진화 루프 (The 5-Step Lean Loop)

```text
1. 글 작성 및 리뷰
       ↓
2. 불편 / 아쉬운 점 즉시 메모
   - "비교 글에서 제품 차이가 한눈에 안 들어옴"
   - "How-to 글은 정상 확인 단계가 빠지면 불안함"
   - "Field Review는 테스트 환경 설명이 부족함"
       ↓
3. 해당 Playbook에 바로 한 줄 반영 (Lightweight Edit)
   - 실패 패턴(DO NOT) 1줄 추가
   - 좋은 흐름(GOOD FLOW) 1줄 보완
   - 불필요하거나 억지스러운 제약 삭제
       ↓
4. 2~3회 반복되는 패턴만 핵심 원칙으로 정식 승격
   - 일회성 문제는 규칙으로 만들지 않고 넘어감
   - 여러 글에서 계속 유용했던 서술만 Playbook 표준으로 고정
       ↓
5. 기존 Playbook으로 담기 힘든 유형이 누적되면 신규 생성
   - 펌웨어/업데이트 글이 계속 생기면 ➔ `PB-NEW-FEATURE-UPDATE`
   - 현장 시공/설치 글이 계속 생기면 ➔ `PB-INSTALLATION-CASE`
```

---

## 2. Playbook 목록 주기적 점검 (5분 퀵 체크)

가끔 전체 Playbook 레지스트리를 볼 때 다음 5가지 상태로만 가볍게 라벨링합니다:

| 분류 | 점검 기준 | 조치 요령 |
| :--- | :--- | :--- |
| **유지 (Healthy)** | 글이 자연스럽게 잘 나오고 손댈 필요 없음 | 그대로 사용 |
| **수정 필요 (Tweak)** | 최근 쓴 글에서 독자 반응이 아쉽거나 Writer가 헷갈려함 | 문장 1~2개 가볍게 수정 |
| **서로 겹침 (Merge)** | 두 Playbook의 작성 흐름이 80% 이상 유사함 | 하나로 합치거나 Secondary로 흡수 |
| **새로 분리 (Split)** | 한 Playbook 안에서 두 가지 다른 글 유형이 억지로 동거 중 | 새로운 `PB-xxx` 파일로 분리 등록 |
| **거의 안 씀 (Dormant)** | 최근 3개월간 생성된 콘텐츠가 없음 | 레지스트리에서 보류 처리 |

---

## 3. 원칙: 규칙의 '다이어트'를 두려워하지 말 것
- 규칙이 늘어날수록 AI Writer는 다시 경직됩니다.
- 새로운 규칙 1개를 넣을 때, **더 이상 필요 없는 형식적인 규칙 1개를 지우는 습관**을 유지합니다.
- Playbook의 분량은 항상 **A4 1~2장 내외**로 가볍게 유지합니다.
