# Writer AI 작성 가이드 v3 — 규칙 조립 진입점

문서 버전: 3.0.0 / 2026-09-30 / 기존 코드 연결은 미구현

전체 계약: [조립형 작성 가이드](authoring/README.md). 이 문서와 authoring의 규격은 이전 작성 가이드의 고정 구성·제품별 단정 예문보다 우선한다. 파일에 가이드가 있다고 모델이 읽은 것으로 간주하지 않는다. 실제 입력에 선택한 MD 본문과 버전/hash가 포함되어야 한다.

## 전체 작성 순서

블로그 부족 키워드 체크 → 주제 설정 → 관련 검색어·장비·기능 키워드 정규화 → 장비+기능/장비+스펙 Fact 추출 → AI 작성 전략 수립 → 연결 주의사항 기계적 로딩·매칭 → 초반·중반·마감 및 블로그 문체 전달 → 이미지 계획·확보·필요시 생성·URL/배치 → 피드백 후 재작성 → 로지텍 AI 검토 → 틀린 내용/지식 변경 후보 대기열 → 관리자 판단 대기열 → 작성 작업 종료 및 콘솔 결과·체크사항.

## 작성 AI에 반드시 전달할 것

- 이번 글의 검색 의도, 독자 질문, 키워드, 포함/제외 범위.
- 검증된 Fact revision과 적용 조건·제약·출처 위치.
- Fact/장비/기능에 연결되어 선택된 주의사항 MD의 실제 본문.
- 선택된 Strategy와 초반·중반·마감 작성 모듈, 필요한 플레이북.
- 승인된 이미지 후보와 글별 AssetNeed/binding, 미해결 자료 요청.
- 재작성 시 해당 원고 revision의 피드백과 해결해야 할 항목.

제품 사실은 가이드 예문이 아니라 근거 데이터에서 읽는다. 모델별 Python 프롬프트에 별도의 제품 사실이나 강제 섹션 구조를 추가하지 않는다. 입력량 제한 때문에 필수 규칙·scope를 조용히 잘라내지 않는다.

## 글 전개

초반에는 오우션 인사말·B2B/데모 문의 안내·주제 예고와 문의 배너를 넣고 검색자의 상황과 조건부 답으로 연결한다. 중반에는 질문에 맞춰 원리·스펙·비교·설정·배선·한계 중 필요한 모듈을 선택하고, 제품을 설명하는 문단 다음에 해당 제품의 소개 글 링크를 넣는다. 실증 기록이 있을 때만 실증 모듈을 사용한다. 마감에는 판단과 다음 행동을 정리하고 마지막 인사말과 동일한 문의 배너를 넣는다. 정확한 문구·원본 데이터 경로·배너 HTML은 [오우션 공통 규칙](authoring/rules/oceantech-brand-and-links.md)을 따른다.

문단은 짧게, 전문용어는 일상어와 연결한다. 분량과 소제목 수는 글별 Strategy의 편집 목표이며 고정 시험 점수가 아니다. 내부 Fact ID와 채점 라벨은 독자용 본문에 노출하지 않되 claim map에는 보존한다.

## 이미지와 검토

이미지는 독자가 눈으로 확인해야 하는 지점에 배치한다. 승인된 공식/자체 자료를 우선 확인하고, 생성 이미지는 개념·상황 설명 목적과 사실 문구를 계획한 뒤 생성·검토한다. 생성 성공이 사용 승인이 아니다. URL은 자산 레코드에 두고 Writer는 자산 ID로 참조한다.

피드백 후 수정본을 다시 검토하고 로지텍 AI에는 정확한 revision과 Claim 목록을 전달한다. 불일치와 판단 불가를 분리해 적재한다. AI 응답이 없거나 파싱되지 않으면 미검토/오류다. 관리자 검토가 남은 경우 작성 작업은 종료할 수 있지만 발행 가능으로 표시하지 않는다.
