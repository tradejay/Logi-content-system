# 정책 편집기와 자동 조립

후속 쿼크나이제이션 작업은 [정책 쿼크나이제이션 TODO](TODO-quarkization.md)의 문제 목록과 AI 탐색 완료 기준을 먼저 확인한다.

다른 AI에게 작업을 맡길 때는 [상세 쿼크나이제이션 작업 가이드](QUARKIZATION-WORK-GUIDE.md)를 전달한다. 문서 마지막에 복사해 사용할 시작 요청이 있다.

기존 Flask 앱의 `/content-ops/policies`에서 연다. 콘텐츠 운영 화면의 ‘정책 관리’ 링크로도 접근한다. 앱에 새 blueprint가 등록되므로 기존 서버는 재시작해야 한다.

1. 정책을 검색하고 자연어 본문·분류·수준·규범·적용 단계를 편집한다.
2. 여러 지시가 섞인 가져온 블록은 `---` 구분자로 분리한다. 각각의 규범과 행위 구조를 검토한다.
3. 변경 이유를 기록하고 저장한다. 저장은 `workspace.json` 편집본과 revision 이력을 만든다.
4. ‘검증·조립 미리보기’에서 가이드·규칙·단계별 프롬프트를 확인한다.
5. 검토자와 정합성 검토 기록을 입력하여 불변 후보 릴리스를 생성한다.
6. 후보를 활성화하면 기존 GuideRepository를 통해 다음 실행에 반영된다. 실행 중인 run은 고정된 기존 릴리스를 사용한다.

원본 MD는 최초 가져오기 출처다. 이후 편집기의 workspace가 조립용 편집본이다. 원본 MD를 직접 바꾸면 출처 해시 불일치로 후보 생성을 차단한다. 원본 변경을 편집본에 재통합하는 UI는 아직 제공하지 않는다.

2026-10-06 편집본 r3에서 제목·버전·표·코드·예문을 출처·참고 목록으로 분리했다. 정책 지시는 문장 단위로 나누고 문서·절의 작업 문맥에 따라 적용 단계를 정리했다. Core는 L1, 도메인 규칙은 L2, 단계 지시는 L3으로 분류한다. 문장 단위 분리는 완성된 원자 정책 의미 분석이 아니다. 복합 지시, 조건절과 대명사의 연결 및 규범 분류에는 추가 의미 검토가 필요하며 화면에 표시한다. 출처 경로·행·해시·절 제목과 분리 전 블록은 보존한다.

기본 목록은 정책 지시만 집계하며 폐기된 가져오기 블록을 제외한다. ‘출처·참고 정보’에서 문서 제목·버전·예시 등을 확인할 수 있다. 적용 단계는 정책 내용의 관련 작업 분류이며 기존 런타임의 가이드 문서 전달 범위를 변경하지 않는다. 런타임은 등록된 문서 단위로 가이드를 전달한다. 문장별 단계만 필터링하는 실행기는 아직 구현하지 않았다.

같은 주체·행위·대상과 겹치는 단계에서 금지와 의무/허용이 충돌하면 빌드를 차단한다. 이 검사에는 행위 구조 입력이 필요하다. 자연어 전체의 의미 충돌 탐지, 권한 수준에 따른 자동 우선순위 해결, 다중 관리자 인증·권한 집행은 구현하지 않았다. 수준은 분류 메타데이터다. 로컬 단일 관리자용으로 사용한다.

새 정책은 선택 단계의 프롬프트에 ID·revision·수준·규범과 함께 추가된다. 기존 문서의 정책은 원래 문서 위치에 조립된다. 새로운 deterministic/pattern 판정기를 선택해도 검사 코드가 자동 생성되지 않으며 연결 전에는 후보 생성을 차단한다. 기존 집필·피드백 응답 필드 계약 변경도 차단한다.

후보에는 정책 snapshot, 검증 결과, 검토자와 검토 기록을 포함하고 manifest 해시로 검증한다. 편집본 변경 후 이전 후보는 활성화할 수 없다. 기존 release 활성화 기능을 그대로 사용하므로 필요하면 검증된 이전 릴리스로 복귀할 수 있다.

검증: `python -m unittest tests.test_policy_manager tests.test_policy_api -v`, `node --check static/policy-editor.js`. API 테스트에는 Flask와 기존 GuideRepository의 PyYAML 의존성이 필요하다.
