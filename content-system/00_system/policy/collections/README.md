# 규칙 용도 분리 — 편집본 r5

이 JSON 파일들은 r5 시점의 검토용 snapshot이다. 최신 편집 데이터는 ../workspace.json이며, 이후 화면에서 수정한 내용이 이 snapshot에 자동 동기화되는 것은 아니다.

- template_design.json: 글 순서, 말투, 독자 질문, 브랜드 문구 및 이미지 슬롯을 템플릿으로 만들 때 사용할 지시.
- runtime_guardrail.json: 모든 템플릿에 계속 적용할 사실·조건·출처·자산 승인·실패 처리 제약.
- runtime_contract.json: 모델 응답 필드, 검토 결과, 이력, 큐, 상태 전이 등 실행 계약.
- reference.json: 제목·버전·예문·표·코드·실행 설명.
- needs_review.json: 어느 용도인지 문맥 검토가 더 필요한 항목.

용도 분류는 문서·절의 성격과 지시 내용에 근거한 1차 분류다. 복합 지시가 남아 있으며 자연어 의미 검토 완료를 뜻하지 않는다. 예를 들어 쉽게 설명하라는 지시와 지원 조건을 보존하라는 지시가 한 문장에 있으면 공통 제약을 우선 보존한다. 템플릿 설계 목록을 근거로 제품별 사실·수치·지원 여부를 만들지 않는다.

다음 템플릿 설계 시 제품 소개/제품 비교/회의실 구성/기능 설명/문제 해결을 시작 유형으로 사용한다. 구조·말투·슬롯 정의는 템플릿에 넣고, 실제 제품 데이터·이미지·다이어그램·URL은 ID로 참조한다. 공통 제약은 템플릿에서 복제하지 않고 별도 묶음으로 적용한다. 템플릿별 검토는 선택된 템플릿의 요구사항을 대조하고, 공통 제약 검토는 모든 글에 수행한다.

현재 실행기는 기존 등록 가이드를 문서 단위로 전달한다. 용도 분리만으로 기존 집필 지시를 제거하지 않았다. 실제 템플릿을 작성·검증하고 실행기의 템플릿 선택·데이터 바인딩을 연결한 후, 템플릿 설계 지시를 매 글의 모델 입력에서 제외하는 별도 릴리스를 만든다.
