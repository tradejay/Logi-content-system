# 정책 쿼크나이제이션 TODO

등록일: 2026-10-06 · 상태: 미착수 · 적용: 다음 정책 쿼크나이제이션 설계·구현·검토 작업

사용자 요청: 정책을 다양한 관점으로 모아 검토할 수 있도록, 현재 탐색의 문제를 다음 쿼크나이제이션 작업에 반영한다.

현재는 문장 단위 분리와 원문 추적까지 구현했다. 의미 분류·관계 연결·누락 검증은 미완성이므로 쿼크나이제이션 완료로 보고하지 않는다.

## 반영할 작업

- [ ] 복합 지시를 의미 단위로 검토한다. 조건·예외·대명사의 문맥을 보존하고, 한 정책 안에 독립된 여러 의무·금지가 남는지 확인한다.
- [ ] 각 정책의 주체·행위·대상·규범·적용 조건·예외·권한 수준을 명시한다. 비어 있는 항목과 의미 검토 상태를 관리한다.
- [ ] 주제·용도·실행 단계·글 구성 요소·출처별로 묶어 조회할 수 있게 한다. 단일 분류를 강요하지 않고 여러 관점을 연결한다.
- [ ] 제품 추천 관련 규칙을 추천·대안·조합·제품 인지·적합 조건·근거·호환·제품 링크·배치 관점으로 연결한다. 문자열 ‘추천’이 없는 관련 규칙도 포함한다.
- [ ] 규칙 사이의 의존·보완·예외·충돌·중복 관계를 기록한다. 함께 읽어야 할 규칙과 서로 적용할 수 없는 조건을 구분한다.
- [ ] 구성 요소 분류를 의미 검토한다. 특히 여러 제품의 링크 규칙이 `unassigned`인 문제, 추천 관련 규칙이 `all_content`나 `body.extension`으로만 분류된 문제를 보완한다.
- [ ] 최근 추가한 제품 보조 노드·선택·배치 설계도 정책 등록 및 검색 대상에 연결한다. 설계 상태와 활성 실행 규칙은 구분한다.
- [ ] workspace 수정 시 파생 collections의 revision을 맞추거나 오래된 목록 사용을 차단한다. 현재 workspace r6 / collections r5 불일치를 해결한다.
- [ ] 정책 원문·버전 변경 시 영향을 받는 의미 분류·관계·그룹을 재검토 대상으로 표시한다. 원문 위치·해시와 변경 이력을 보존한다.
- [ ] 편집기에서 조회되는 정책과 실제 AI 입력에 선택되는 정책의 경로를 명시한다. 분류만 바꾼 상태를 실행 반영으로 보고하지 않는다.

## AI 탐색 관점의 완료 기준

- [ ] AI가 ‘제품 추천 규칙’ 한 주제를 조회했을 때 관련 정책과 공통 제약·연결 관계·원문 위치·검토 상태를 함께 읽을 수 있다.
- [ ] AI가 추천·부속·호환·재사용 등 여러 검색어를 스스로 추측해 원문 전체를 재탐색하지 않아도 핵심 규칙을 찾을 수 있다.
- [ ] 사람이 검토한 관련 정책 목록과 조회 결과를 대조해 누락·불필요한 포함을 기록한다. 다른 주제에도 같은 검증을 수행한다.
- [ ] 최초 조회부터 AI가 규칙을 이해하고 답을 만들 때까지의 실제 경과 시간, 조회 횟수, 원문 재검색 횟수를 기록한다. 파일 검색 속도를 AI 탐색 시간으로 대신 제시하지 않는다.
- [ ] 의미·관계 검토가 완료되지 않은 정책은 미완성으로 표시한다. 단순 문장 분리나 자동 키워드 분류만으로 완료를 선언하지 않는다.
