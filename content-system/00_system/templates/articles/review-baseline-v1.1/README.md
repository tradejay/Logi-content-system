## 제품 소개

이 제품이 내 불편을 해결할 구성에 필요한가?

- 제품·기능 기본 설명: 도입의 불편·원하는 변화에 이어 제품의 기본 의미와 이번 구성에서 맡는 역할을 첫 기능 설명에 포함
- 질문별 핵심 설명: 고객 불편 → 필요한 변화 → 기능의 쉬운 설명과 Fact 근거
- 비교: 구매 이유에 필요한 기능·모드 차이를 같은 기준으로 설명 / 포함 조건: 기능 차이가 구매 이유 또는 독자 질문의 핵심일 때
- 구성·배선·사용 모습: 구매할 것·재사용할 것·장비 역할·회의 사용 모습 설명. 연결 관계가 핵심일 때만 배선 상세와 도식 추가
- 스펙 해석: 판단에 필요한 수치·단위·측정 조건만 해석 / 포함 조건: 구매 판단에 수치가 필요한 경우
- 적용 조건·주의사항: 제품·모드·플랫폼·버전의 적용 조건과 한계
- 조건부 추가 장비: 남는 문제를 보완하는 부속의 역할·근거 / 포함 조건: 기본 구성으로 해결되지 않는 문제가 있는 경우

독립 개요 장·고정 문단 수를 강제하지 않는다. 각 설명에 질문·근거·조건·시각 자료를 연결한다.

## 제품 비교

같은 사용 요구에서 어느 선택지가 적합한가?

- 제품·기능 기본 설명: 비교할 제품 또는 운영 방식의 기본 의미와 공통 전제
- 비교: 하나의 결정 질문과 동일한 환경·기준에서 확인된 차이·적합 조건·한계를 설명. 제품과 운영 방식·부속 역할을 섞어 비교하지 않음
- 구성·배선·사용 모습: 선택지별 실제 사용 모습; 상세 연결 절차는 필요할 때만 / 포함 조건: 사용 모습이 선택에 영향을 주는 경우
- 적용 조건·주의사항: 비교 범위·지원 조건·차이의 한계
- 질문별 핵심 설명: 환경별 선택 기준과 기본 추천의 이유; 효과를 보장하지 않음

독립 개요 장·고정 문단 수를 강제하지 않는다. 각 설명에 질문·근거·조건·시각 자료를 연결한다.

## 회의실 구성

기존 공간과 장비로 무엇을 구매·재사용해 어떻게 구성할까?

- 제품·기능 기본 설명: 기본 구성의 장비별 역할; 서로 대체하지 않는 부속 구분
- 구성·배선·사용 모습: 확인된 기본 연결 관계와 사용 흐름; 도식 ID 바인딩
- 설정 방법: 공식 설정·연결 순서와 정상 동작 확인 / 포함 조건: 검색 의도가 설치·설정이거나 실행 절차가 필요한 경우
- 적용 조건·주의사항: 호환성·버전·설치 제약 및 미확정 조건
- 조건부 추가 장비: 어떤 문제가 남을 때 부속이 필요한지 설명 / 포함 조건: 추가 장비의 필요성이 근거로 확인된 경우

독립 개요 장·고정 문단 수를 강제하지 않는다. 각 설명에 질문·근거·조건·시각 자료를 연결한다.

## 기능 설명

이 기능은 무엇을 하며 내 문제에 언제 필요한가?

- 제품·기능 기본 설명: 기능을 일상어로 정의하고 제품의 역할과 연결
- 원리 설명: 공식 확인된 입력·동작·결과·확인 범위까지만 설명. 미공개 내부 원리를 채우지 않음 / 포함 조건: 왜·어떻게 작동하는지가 핵심 질문이며 공식 근거가 확보된 경우
- 질문별 핵심 설명: 사용 상황과 화면·음향 등 독자가 확인할 모습
- 비교: 혼동하는 기능·모드가 있으면 같은 기준으로 차이 설명 / 포함 조건: 차이 설명이 독자 질문 해결에 필요한 경우
- 적용 조건·주의사항: 지원 제품·모드·플랫폼·버전과 확인된 한계

독립 개요 장·고정 문단 수를 강제하지 않는다. 각 설명에 질문·근거·조건·시각 자료를 연결한다.

## 문제 해결

증상과 환경을 어떻게 확인하고 공식 절차로 조치·정상 확인할까?

- 질문별 핵심 설명: 증상·발생 환경·범위를 확인; 원인을 미리 단정하지 않음
- 적용 조건·주의사항: 점검 전 제품·버전·권한·호환성 및 작업 전제
- 설정 방법: 가능 원인별 공식 확인 방법 → 조치 → 정상 확인; 분기별 반복
- 구성·배선·사용 모습: 연결 관계가 원인 판단에 필요한 경우 도식 설명 / 포함 조건: 배선·구성 점검이 필요한 경우
- 질문별 핵심 설명: 미해결 시 필요한 증상·환경·점검 기록과 지원 경로를 안내. 근거 없이 원인을 단정하거나 장비 구매를 결론으로 삼지 않음

독립 개요 장·고정 문단 수를 강제하지 않는다. 각 설명에 질문·근거·조건·시각 자료를 연결한다.
