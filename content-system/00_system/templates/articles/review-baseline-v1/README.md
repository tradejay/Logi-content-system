# 네이버 화상회의 블로그 글 템플릿 설계

설계 초안. 실행기 연결·운영 활성화 전이며 완성 원고를 생성하지 않았다.

구성 요소는 문단이나 H2 개수가 아니다. 인접 역할은 자연스럽게 합칠 수 있다. 시작·마감 공통 순서를 보존하고 본문은 독자 질문에 따라 조정한다.

공통 시작: 제목 → 첫인사 → B2B 안내 → 고민 공감·주제 예고 → 문의 문구·배너 → 본문 연결 → 전제·질문·조건부 핵심 답

공통 마감: 핵심 답·결론 회수 → 다음 행동 → 가치 요약·소회 → 상담/데모 연결 → 맺음 인사 → 문의 문구·배너

## 제품 소개

이 제품이 내 불편을 해결할 구성에 필요한가?

| 순서 | 역할 | 내용 | 포함 조건 |
|---|---|---|---|
| 1 | 제품·기능 기본 설명 | 어떤 제품이며 이번 환경에서 어떤 역할을 하는지 설명 | 기본 포함 |
| 2 | 질문별 핵심 설명 | 고객 불편 → 필요한 변화 → 기능의 쉬운 설명과 Fact 근거 | 기본 포함 |
| 3 | 구성·배선·사용 모습 | 기존 장비와 함께 어떻게 회의를 사용하는지 기본 구성 설명 | 기본 포함 |
| 4 | 스펙 해석 | 판단에 필요한 수치·단위·측정 조건만 해석 | 구매 판단에 수치가 필요한 경우 |
| 5 | 적용 조건·주의사항 | 제품·모드·플랫폼·버전의 적용 조건과 한계 | 기본 포함 |
| 6 | 조건부 추가 장비 | 남는 문제를 보완하는 부속의 역할·근거 | 기본 구성으로 해결되지 않는 문제가 있는 경우 |

연결 주제: TOPIC-PROP-006, TOPIC-PROP-007, TOPIC-PROP-008, TOPIC-PROP-009

## 회의실 구성

기존 공간과 장비로 무엇을 구매·재사용해 어떻게 구성할까?

| 순서 | 역할 | 내용 | 포함 조건 |
|---|---|---|---|
| 1 | 제품·기능 기본 설명 | 기본 구성의 장비별 역할; 서로 대체하지 않는 부속 구분 | 기본 포함 |
| 2 | 구성·배선·사용 모습 | 확인된 기본 연결 관계와 사용 흐름; 도식 ID 바인딩 | 기본 포함 |
| 3 | 설정 방법 | 공식 설정·연결 순서와 정상 동작 확인 | 검색 의도가 설치·설정이거나 실행 절차가 필요한 경우 |

| 5 | 조건부 추가 장비 | 어떤 문제가 남을 때 부속이 필요한지 설명 | 추가 장비의 필요성이 근거로 확인된 경우 |

## 공통 제약과 자료 바인딩

제품 설명 직후 제품 소개 링크를 연결한다. 이미지·GIF·도식·표는 필요한 설명 위치에 배치하며 개별 장으로 강제하지 않는다. 지원 조건은 주장 옆에 남기며 독립 주의사항 장은 필요할 때만 만든다. 실제 기록이 없는 실증/사례는 넣지 않는다.

템플릿 설계 규칙은 구조 설계에 참조하고, 사실·조건·출처·승인 및 실행·출력 계약은 매 글에 계속 적용한다. 미분류 설계 규칙을 자동 폐기하지 않는다. JSON의 정책 ID 연결은 1차 분류에 기반하므로 검토 후 확정한다.

20개 후보 제목의 성능 강화·최적·인원수·인증·원인 단정은 검증 대상이다. 관련 근거가 없으면 중립 제목으로 수정한다. 문제 해결 글의 결론은 장비 구매를 전제로 하지 않는다.

파일: common.json(공통 구조·제약 참조), catalog.json(유형별 본문), topic-bindings.json(20개 주제 연결).
