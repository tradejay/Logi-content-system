문제 → 이유 → 해결 기능/절차 → 제품·구성 적용 → 판단을 기본으로 한다. 5개 유형 모두 제품 정의 앞에 문제 장면·선택 고민을 배치했다. 공통 시작·마감은 common.json, 유형별 흐름은 catalog.json에 정의했다.

인사·주제 예고는 짧게 연결하고 본문 첫 설명에서 문제를 구체화한다. 기존 기업 안내·양쪽 문의 배너·제품 설명 위치의 링크를 유지한다. 제품·기능·부속의 실제 자료는 설명 위치에 연결하며 실증은 실제 기록이 있을 때만 넣는다.

샘플의 “오늘은 …” 고정 문구·무료 대여·제품 수치·실증 주장은 복제하지 않는다. 편집기 메뉴와 ASSET_REQUIRED 표시는 원고 구성에 포함하지 않는다.

작성 계획이며 실제 원고 생성·사실 검증·운영 활성화는 아직 수행하지 않았다.
