# 제품 추천 기록·검증·빈도 관리

Version: 1.0.0 / 2026-10-07

콘텐츠 관리 과정에서 제품 추천을 추적하기 위한 기록·점검 가이드다. 자동 추출·통계 화면·운영 파이프라인 연결은 아직 구현하지 않았다. 기존 콘텐츠 상태와 Writer 응답 계약은 유지한다.

## 1. 관리 목적과 구분

글을 작성·수정·발행하면서 어떤 제품을 어떤 독자 요구에 추천했는지 추적한다. 제품 이름이 나온 횟수를 추천 횟수로 간주하지 않는다.

| 분류 | 의미 | 추천 빈도에 포함 |
|---|---|---|
| 단순 언급 | 이름만 등장하거나 다른 제품 설명의 배경으로 사용 | 아니오 |
| 제품 인지·소개 | 이름·역할·기능을 설명하지만 구매·도입을 권하지 않음 | 아니오, 소개 빈도로 별도 집계 |
| 추천 | 특정 요구·환경에서 구매·도입·사용·재사용을 권함 | 예 |
| 비교 후보 | 비교했으나 선택 결론으로 권하지 않은 후보 | 아니오, 비교 노출로 별도 집계 |
| 부적합·비추천 | 해당 조건에 맞지 않는다고 설명 | 아니오 |

제품 소개 글이라는 유형만으로 추천으로 판정하지 않는다. 비교 글은 조건별로 권한 제품만 추천으로 기록한다. 설정·배치 조정으로 해결한 글은 관련 제품의 이름이 있어도 구매 추천으로 바꾸지 않는다.

## 2. 글별 기록

`content_id`와 원고 revision·해시를 기준으로 제품별 기록을 남긴다. 제품은 제품 레지스트리의 표준 ID로 정규화하고 모델·세대를 구분한다. 이름이 모호하면 확인 대기 상태로 두며 임의 제품으로 연결하지 않는다.

별도 관리 레코드의 제안 필드는 아래와 같다. 현재 Writer 응답에 이 필드를 강제로 추가하거나 Registry CSV 열을 임의로 변경하지 않는다.

| 필드 | 기록 내용 |
|---|---|
| content_id, draft_revision, draft_sha256 | 어느 글의 어떤 원고인지 |
| product_id, product_name | 확인된 제품 ID와 이름 |
| classification | mention / awareness / recommendation / comparison_candidate / not_recommended |
| occurrences | 문단·구성 요소·본문 또는 보조 노드 위치·판정 근거 문장과 locator |
| reader_question, recommendation_reason | 어떤 요구에 왜 적합한지; 추천일 때 필수 |
| fit_conditions, compatibility_limits | 공간·기존 장비·플랫폼·모드·펌웨어·라이선스 등 적용 조건과 중요한 제약 |
| acquisition | acquire(도입) / reuse(재사용) / consider(선택 후보) |
| group_id, relationship | 대안 / 함께 쓰는 구성 / 조건부 추가 / 인지와 같은 제품 간 관계 |
| base_group_id, remaining_problem | 조건부 추가가 연결된 기본 구성과 남는 문제 |
| fact_source_bindings | Claim·Fact ID/revision·공식 source locator, 구성/호환 근거 |
| product_blog_link | 제품 ID로 조회한 소개 URL과 확인 시점 |
| review_status, reviewer, reviewed_at | pending / verified / rejected 및 검토자·검토 시점 |
| unresolved_items | 근거 부족·조건 누락·ID 모호·링크 오류 등 미해결 이유 |
| publication_ref | 실제 게시 URL/post ID·게시일·게시된 revision; 초안에는 발행된 것처럼 기록하지 않음 |

한 제품이 본문과 보조 노드에 반복되면 occurrence는 각각 기록하되 글별 제품 레코드는 합친다. 서로 다른 조건의 추천은 근거와 조건을 occurrence별로 보존한다. 한 문단에서 근거가 부족하면 다른 문단의 검증으로 덮지 않는다. 단순 언급과 추천이 함께 있으면 추천 문장을 확인하여 글별 추천 여부를 정한다.

## 3. 작성 과정의 검증 시점

1. **기획**: 추천할 제품·묶음·질문·배치를 계획한다. 이전 추천 이력과 빈도를 참고하되 과거 추천을 현재 호환성 근거로 쓰지 않는다.
2. **집필·재작성 후**: 실제 본문에서 추천을 추출하고 기획과 대조한다. 추가·삭제·인지에서 추천으로 변경된 제품을 표시한다. 이름 일치만으로 추천 판정을 확정하지 않는다.
3. **QA**: 추천 문장, 독자 요구, 제품 역할, 적용 조건, 기술 주장과 Fact/source, 제품 링크를 확인한다. 구성품을 다른 장비의 기능으로 오인하거나 대안·조합·조건부 추가를 섞지 않았는지도 확인한다.
4. **원고 변경**: 변경된 원고 revision·해시에 맞춰 기록을 갱신한다. 추천·조건·근거가 바뀌면 기존 추천 검토 결과를 그대로 승계하지 않는다. 이전 기록은 이력으로 보존한다.
5. **발행 후**: 실제 게시 URL·게시된 revision을 확인하여 발행 이력에 연결한다. 실제 게시본이 승인 원고와 다르면 차이를 확인하기 전 같은 추천 목록으로 확정하지 않는다.
6. **수정 발행·삭제·비공개**: 현재 게시본의 제품 목록과 공개 여부를 갱신하고 과거 발행 이벤트는 보존한다. 내부 원고를 수정한 것만으로 실제 게시본의 기록을 덮어쓰지 않는다.

검증 실패·근거 부족은 해당 항목의 상태와 이유로 남긴다. 추천 빈도 보고서를 만들기 위해 확인되지 않은 제품 ID·조건을 만들어 채우지 않는다.

## 4. 집계 기준

집계 시 조회 기간, 대상 글, 기준 시점, 공개 상태, 사용한 게시 revision, 검토·데이터 수집 완료 여부를 함께 표시한다. 초안·계획과 실제 게시 글은 별도로 집계한다.

| 지표 | 정의 |
|---|---|
| 제품별 추천 글 수 | 기간 내 실제 발행한 대상 글 중 해당 제품을 추천한 고유 content_id 수 |
| 제품별 추천 비율 | 해당 제품 추천 글 수 / 기간 내 대상 발행 글 수. 한 글이 여러 제품을 추천할 수 있으므로 제품별 비율 합계는 100%를 넘을 수 있음 |
| 제품별 소개·비교 노출 | 추천과 분리한 소개 글 수·비교 후보 글 수 |
| 마지막 추천 | 실제 게시일 기준 마지막 추천 글과 날짜. 수정 게시일은 별도로 표시 |
| 유형·주제별 추천 | 문제 해결 / 기능 설명 / 구성 / 비교 / 제품 소개, 독자 질문·키워드별 분포 |
| 위치·조건별 추천 | 본문 / 보조 노드, 공간·플랫폼·운영 모드·기존 장비 조건별 분포 |
| 조합 빈도 | 같은 구성 묶음에서 함께 추천한 제품 ID 조합별 글 수. 대안 후보를 구매 조합으로 집계하지 않음 |
| 조건부 추가 빈도 | 기본 구성별로 특정 추가 제품을 권한 글 수와 남는 문제·조건 |
| 검증 현황 | 확인 완료·검토 대기·거절·오래된 근거·누락 기록 수 |

기본 집계는 **같은 글·같은 제품을 한 번** 센다. 문단 반복, 링크 반복, 재작성 run, 여러 원고 revision을 새 추천 글로 더하지 않는다. 재발행 이벤트 수가 필요하면 추천 글 수와 별도 지표로 표시한다.

기간 분석은 예를 들어 최근 30일·90일 또는 사용자가 지정한 기간으로 수행할 수 있다. 전체 운영 이력도 별도 조회할 수 있어야 한다. 새 글에서 예전에 추천했던 제품을 추천하면 새 content_id로 한 번 추가한다.

기간 내 신규 발행 실적과 현재 공개 콘텐츠 전체의 추천 분포는 다른 지표다. 기간 전에 발행하고 기간 안에 수정한 글은 신규 발행 수에 더하지 않으며 수정 이력 분석으로 확인한다. 조합은 제품 ID를 정렬·중복 제거한 키로 비교하되 모델·세대·구성 모드는 보존한다.

미수집·검토 대기 글은 제외 수와 사유를 표시한다. 수집 완료 글만으로 비율을 계산했다면 분모를 ‘수집 완료 발행 글’로 명시한다. 기록이 없다는 이유로 추천 0회나 해당 제품에 대한 콘텐츠가 없다고 확정하지 않는다.

## 5. 콘텐츠 관리·다음 주제 선정에 활용

- 같은 제품·같은 질문·같은 조건이 반복되면 신규 글과 기존 글 보완 중 무엇이 적합한지 확인한다.
- 특정 제품에 추천이 집중됐는지, 제품·주제·환경 조건 중 설명이 부족한 범위가 있는지 살펴본다.
- 추천이 적은 제품을 채우기 위해 무관한 제품을 넣거나 모든 제품을 같은 횟수로 추천하지 않는다. 빈도는 점검 신호이며 자동 선정·추천 금지 기준이 아니다.
- 근거·지원 범위·제품 링크가 변경되면 해당 제품을 추천한 글을 찾아 재검토한다. 영향은 Claim·적용 조건·사용한 revision에 따라 판단한다.
- 키워드 AI는 주제 선정 시 이전 추천 글의 질문·조건·시점을 참고한다. 추천 빈도 하나로 수요나 신규 글 필요성을 판단하지 않는다.

매일 점검을 강제하지 않는다. 글 작성·수정·발행 시 기록을 갱신하고, 주제 선정 또는 콘텐츠 묶음 검토 시 빈도와 편중을 확인한다. 예약 작업은 별도 사용자 요청이 있을 때 설정한다.

## 6. 단계별 책임과 구현 범위

| 역할 | 책임 |
|---|---|
| 기획 | 과거 추천 이력 확인, 새 추천 이유·조건·묶음 계획 |
| 집필 | 계획과 실제 추천 문장의 차이 기록 |
| QA | 추천 분류·기술 근거·조건·링크 검증 |
| 콘텐츠 관리자 | 실제 게시본과 연결, 변경 이력·집계 범위·누락 확인 |
| 키워드 AI | 추천 이력을 다음 주제 선정·기존 글 보완 판단에 참고 |

이번 추가는 운영 관리 가이드다. 자동 추천 추출기·저장 레지스트리·통계 화면·런타임 연동은 후속 구현 대상이다. 기존 20개 예시 글을 실제 발행·검증 완료 기록으로 소급 등록하지 않는다.
