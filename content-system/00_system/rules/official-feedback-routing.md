# SYS-OFFICIAL-FEEDBACK-007 — 공식 검토 해석과 집필 수정 연결

Version: 1.0.0 / 2026-10-12

GUIDE-05-FEEDBACK-V2N0070, V2N0072, V2N0122를 실행 경로에 적용한다. 로지텍 AI는 기술 검토를 맡고, 일반 설명문도 수용한다. JSON·규칙 수신·자동화 실행 책임을 제조사 AI에 요구하지 않는다. 원문과 원고 revision/hash를 보존한다.

내부 검토 AI는 응답 형식이나 confirmed 표기 여부에 관계없이 원고, Claim, 연결 Fact·출처와 공식 응답 전체를 함께 읽어 진행/수정/보류를 판정한다. 유효한 JSON이라는 이유로 의미 판정을 생략하지 않는다. 형식 거절과 일반적 역할 면책은 기술 불일치로 분류하지 않는다. 구체적인 정정·범위 제한은 체크 표시보다 우선한다. 문서에 명시되지 않았다는 답변을 기능 부재나 확인됨으로 확대하지 않는다. 빠진 Claim과 판단 불가는 긍정으로 바꾸지 않는다.

판정은 Claim별로 정확히 한 번 기록한다. 확인된 Claim에는 근거와 공식 원문의 실제 인용이 필요하다. 수정 요청에는 Claim ID, 명칭/사실 분류, 구체적 변경 요청, 실제 원문 인용이 필요하다. 원문에 없는 정정·URL·Fact를 창작하지 않는다. 기존 지식을 직접 변경하지 않는다.

- 진행: 모든 기술 Claim이 확인되고 수정 요청이 없으면 집필 호출을 추가하지 않는다.
- 수정: 실제 수정 요청이 있으면 기존 집필 AI에 원고·피드백·공식 원문·보존 Fact·기존 자산 계획을 전달한다. 수정 위치를 특정할 수 있으면 해당 블록만 수정하고 나머지를 보존한다. 불필요한 수정이라고 판단하면 changes에 이유를 기록해 유지할 수 있으나 검토를 우회할 수는 없다.
- 보류: 판단 불가·상충·변환 오류이면 관리자 확인으로 남기고 이미지 제작·승인으로 진행하지 않는다.

수정본은 새 revision으로 저장하고 원고/Claim/블록/자산 계약, 자체 검토 및 공식 재검토를 수행한다. 현재 구현은 명칭 수정도 공식 재검토하여 보수적으로 판정한다. 공식 수정은 기본 1회이며 설정 pipeline_official_repair_limit은 0~3을 허용한다. 반복 지적·한도 소진·QA 실패는 REVISION_REQUIRED로 종료한다. 작성 AI가 수정하지 않았다는 이유만으로 지적 사항이 해결된 것으로 처리하지 않는다.

로그: rN.official(제조사 응답), rN.official-interpret(내부 AI 수신 확인·토큰·판정), reviews/rN.writer-handoff.json(집필 전달), rN+1.write/feedback 및 새 공식 검토. 외부 응답의 receipt는 확인되지 않았다고 구분하며 내부 AI receipt 검증으로 대체 기록한다. 최종 기계 검증은 원문·판정·원고 hash·Claim 범위와 로그 연결을 확인한다. 의미적 정확성을 기계 검증만으로 보장하지 않는다.

이미지 제작은 수정 후 QA·공식 검토가 통과한 원고에서 진행한다. 이미지 후보 승인과 최종 발행 승인은 별도이다.
