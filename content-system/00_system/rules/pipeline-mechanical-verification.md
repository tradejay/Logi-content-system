# SYS-PIPELINE-VERIFY-005 — 실행 로그 통합 검증

2026-10-08. 실행 기록만 읽는 검증이며 네트워크/API 호출을 하지 않는다. 실행 종료 시 `pipeline-verification.json`을 자동 생성한다. 관리자 승인·출처 원문 확인·글의 의미적 적합성 판단은 별도다.

## 실행

프로젝트 루트에서:

```powershell
python -m scripts.verify_content_pipeline "working/<content_id>/runs/<run_id>" --output "audit/pipeline-verification.json"
```

## 검사 범위

1. `execution-contract.json`의 산출물 목록·해시, 실행 ID, 종료 상태와 실행 결과 일치.
2. 호출 목록·순서와 실제 프롬프트/규칙 로그 일치. 규칙 본문·ID·수신 receipt·토큰 제한·블록 계약은 기존 로그 검증기를 함께 사용.
3. 웹 검색 요청의 지시 해시·요청 지문·정상 종료 증빙, AVIXA·PSNI 도메인/신뢰 정책, Google 인용 문장·출처 인덱스 연결, 선별 입력과 검색 자료 일치.
4. 관련 글 / 개별 사실 대체 / 제품 Fact만 사용 분기와 선별 출력 일치. 선별 실패는 기록된 관리자 항목·대체 분기·경고로 구분.
5. 기획 참고자료·규칙이 기획/집필/피드백 호출에 전달됐는지 확인. 모든 참고자료의 본문 사용을 강제하지 않음.
6. 기획 → 집필 → 피드백 → 재작성 또는 공식 검토 순서, 재개 실행 출처와 승계 자료 일치.
7. 제품 Fact ID·수치·범위 보존, 기관 자료의 제품 Fact 무단 승격 탐지. 전략·자산 계획·바인딩 연결 확인.
8. 저장된 초안과 Writer 응답·피드백 검토 원고 일치, 최종 원고 해시/Claim/이미지 자리표시자/미해결 항목 계약 확인.
9. 완료 실행은 QA 통과 및 원고 전문·Claim·연결 Fact·출처가 공식 검토에 전달됐는지 확인. 공식 응답이 모든 Claim을 근거와 함께 확인했는지 검사.

## 판정

- `PASS`: 기록 무결성과 연결 검사 통과, 전체 실행 완료.
- `PASS_WITH_WARNINGS`: 통과하되 기록된 선택적 호출 실패 등이 있음. 경고와 `pipeline_complete`를 함께 확인.
- `NOT_COMPLETE`: 사전 점검·근거 부족·실행 중단 등으로 전체 실행이 끝나지 않음. 이를 완료로 표시하지 않음.
- `FAIL`: 누락·변조·단계/데이터 불일치 발견.
- `UNSUPPORTED`: 실행 계약 없는 구버전 로그. 기존 `verify_policy_call_logs`로 호출 기록은 검사할 수 있으나 전체 검증 통과로 승격하지 않음.

`valid`는 기록과 연결 계약의 통과 여부이고 `pipeline_complete`는 전체 실행 완료 여부다. 이 검사는 글의 논리·추천의 적합성·문장별 자연어 규칙 준수를 증명하지 않는다. `semantic_compliance=not_evaluated`를 유지한다.

검증기는 실행 종료 후 보고서를 남기며 원고 상태나 관리자 승인을 자동으로 변경하지 않는다. 정기 재검사는 위 명령을 호출할 수 있지만 주기적 예약은 별도로 설정해야 한다. 실행 계약과 해시는 파일 변경 탐지용이며 외부 서명/변조 방지 저장소를 대체하지 않는다.
