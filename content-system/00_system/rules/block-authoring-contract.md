# 블록별 집필 입력·출력·검증 계약

2026-10-08 구현. 전체 원고 집필 호출 안에 블록별 계약을 자동조립한다.
활성 가이드 릴리스를 바꾸지 않고, 선택한 릴리스 문서 규칙과 기존 블록 가이드 카탈로그를 연결한다.

## 실행

1. 전략 AI가 `content_blocks`를 작성한다. 블록 항목은 `id`, `roles`, `purpose`, `fact_ids`다. 승인된 사용자 계획이 있으면 보존한다.
2. 집필 전 각 역할의 목적·작성 가이드·피해야 할 표현·검토 질문을 카탈로그에서 가져온다. 선택된 릴리스 문서 규칙 중 연결된 규칙을 `rule_ids`로 배정한다.
3. 입력 `block_plan`에 순서·역할·목적·Fact ID·규칙 별칭·가이드가 전달된다. 규칙 본문은 호출 공통 목록에서 한 번 제공한다.
4. AI는 전체 글을 한 번에 집필하되 `blocks`도 반환한다. 각 항목은 `id`, `markdown`, `claim_ids`다. 기술 주장에 사용한 Fact는 해당 블록에 배정된 것만 사용한다.
5. 전체 `markdown`은 블록 markdown을 순서대로 두 줄바꿈으로 조립한 문자열과 동일해야 한다. 기존 claims·이미지 Need·미해결 항목 계약도 유지한다.
6. 기계 검증은 블록 ID·순서·누락·빈 내용·조립 일치·Claim 소속·Fact 범위를 확인한다. 실패를 QA 오류에 포함해 승인을 막는다.
7. 전체 피드백 AI는 이슈에 `block_id`를 지정한다. 모든 이슈가 블록/Claim에 명확하게 연결되면 `repair_block_ids`를 전달한다. 다른 블록과 그 Claim을 수정하면 오류다. 전체 문제·누락 Claim·계약 오류·위치 불명확 이슈는 전체 재작성한다.

선택 수정도 현재는 전체 blocks 배열을 반환하는 한 번의 집필 호출이다. 블록마다 별도 호출하거나 패치만 출력하는 실행기는 아니다.
기계 검증은 작성 계약을 확인하며 의미적 규칙 준수는 AI/관리자 검토가 필요하다.

## 가이드·식별

기존 `content-block-guides.json`의 역할별 가이드를 가져오고 카탈로그 SHA-256과 작업 공간 revision을 기록한다.
`rule_ids`는 실제 전달된 활성 릴리스 문서 규칙이다. 카탈로그의 원자 정책 ID는 출처 참조로 서버에 기록되며, 해당 원자 전체를 활성화하거나 전송했다고 간주하지 않는다.
모델에는 짧은 규칙 별칭을 전달하고 긴 원자 출처 ID 목록은 서버 로그에만 둔다.
모든 블록이 공통 규칙도 적용받으며 블록 규칙 배정은 그 중 해당 역할에 연결된 문서 규칙을 표시한다.

전략에 명시적 블록 계획이 없으면 기존 opening/body/closing 순서를 보존해 작성 단위를 만든다.
본문 역할을 자연어 문장으로 추정하지 않으며 `body.explanation` 기본 역할과 `fallback_needs_review`를 기록한다.
이 경우 블록별 정밀 역할 지정까지 완료했다고 주장하지 않는다. Fact ID를 명시하지 않은 블록에는 해당 호출의 Fact 목록을 제공하며 별도 로그에 실제 범위를 남긴다.

## 로그와 재개

- `block-plan/*.json`: 원본 규칙 ID·가이드 출처·순서·Fact·카탈로그 해시.
- `rule-audit/*.json`의 `block_assignments`: 블록별 실제 규칙 배정 대응표.
- `block-review/*.json`: 모델 블록 출력, 기계 검증 결과, 선택 수정 대상.
- 실행 내역 UI에 블록 계약/검증 항목 노출.
- 읽기 전용 `verify_policy_call_logs`는 규칙 배정 로그와 실제 전송, 실제 응답의 블록 계약을 재검증한다.
- 재개 실행에서도 저장된 블록 계약으로 기존 원고를 재검증하고 오류를 승계한다.

원본 작성 프롬프트 파일이나 활성 정책 릴리스는 변경하지 않았다. 블록 출력 계약은 전송 시 추가하는 런타임 계약이다.
